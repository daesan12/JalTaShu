실제 서비스 DB를 읽기 전용으로 덤프한 뒤 **네트워크가 차단된 임시 MySQL**에 복원하고, 그 복원본에서만 개인정보를 제거해 다시 덤프했다. 운영·스테이징 원본 DB는 수정하지 않았다. 제출 파일은 압축 검사와 별도 임시 MySQL 복원을 통과했으며, 두 DB 모두 테이블 19개가 복원됐다.

원본 백업에는 실제 OAuth 사용자 식별자·닉네임, 관리자 비밀번호 해시, FCM 토큰, 사용자 제보와 위치 정보가 포함될 수 있어 Git에 올리지 않았다. 제출본에서는 운영 사용자와 관리자 행을 제외했고, 스테이징의 시연용 사용자 14,500명의 닉네임·OAuth 식별자를 가명으로 바꿨다. FCM 토큰, 제보·신고, 최근 장소, 알림, 관리자 공지·팝업, 약관 동의, 정지 기록, 이벤트 페이로드와 실제 사용자 이용 기록은 제외했다. 남겨둔 시연용 경로 157,751건의 상세 좌표 JSON은 비웠다.

복원 검증 결과 운영 사용자 0건, 스테이징 시연용 사용자 14,500건, FCM 토큰 0건, 제보 0건, 실제 사용자 식별자 0건이었다. 이 파일은 **제출·시연을 위한 익명화 사본**이므로 운영 데이터의 원본 백업을 대신하지 않는다. 복원 시험은 빈 로컬/임시 MySQL에서만 수행하고, 실행 중인 운영·스테이징 DB에는 적용하지 않는다.

분산처리용 `tashu_data` DB의 `station_availability` 실데이터는 약 3.3GB여서 이 Git 덤프에 포함하지 않았다. 해당 DB의 테이블 정의는 [`infra/mysql/schema/tashu-data.sql`](../infra/mysql/schema/tashu-data.sql)에 있다. 전체 비공개 운영 백업은 Server A의 백업 절차로 별도 관리한다.
