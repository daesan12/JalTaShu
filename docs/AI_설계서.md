# 타슈 AI 설계서 — 데이터부터 서빙까지

**목표**: 사용자가 대여소에 도착하는 시점(5~15분 뒤)의 ①예상 잔여 대수와 ②못 빌릴 확률을 산출한다. ①은 화면 표시용, ②는 여정 추천의 기대 이동비용 수식(`정상 이동시간 + 못 빌릴 확률 × 실패 시 추가시간`)의 입력이다.

> 이 문서의 수치는 전부 실데이터 검증 완료 값이다 (대여이력 253만+ 건 분석, 과산포·베이스라인 실측).

---

## 0. 설계 원칙 (제약에서 나온 결론)

- 잔여량 과거 시계열은 세상에 없고 수집 가능 기간이 ~3주뿐 → **학습은 44개월 대여이력으로, 검증은 3주 스냅샷으로** 역할 분리
- 미래 잔여 = **현재 잔여(실시간 API가 항상 제공) + 예측 순변화(이력 학습 모델)** — 스냅샷 축적 없이도 서비스 성립
- 확률은 분포로 도출(포아송 계열) → 후반에 스냅샷 분류기와 비교(어블레이션)

## 1. 데이터 (역할별)

| 역할 | 데이터 | 사용 내용 |
|---|---|---|
| **학습 (라벨+피처)** | 타슈 대여이력 CSV 44개월(2022.8~2026.3, 4.4GB) | 대여소×15분 버킷별 대여 수·반납 수 집계 → 회귀 라벨. OD 행렬 → 자전거 구간 소요시간 |
| **피처 (외부변수)** | 기상청 초단기실황·예보 / 특일정보 | 시간당 강수, 기온, 공휴일 유형 (과거분은 Open-Meteo 아카이브로 조인) |
| **실시간 입력** | KLID API 45초 폴링(2콜, numOfRows=1000 × pageNo 1·2) → Kafka → DB/S3 | 현재 잔여 대수 s (예측의 출발점) + delta 모멘텀 |
| **검증 전용** | 자체 수집 스냅샷 ~3주 | 캘리브레이션, 백테스트. 학습에 사용 안 함 |

전처리 규칙(실확인): 대여일시로 파티셔닝(파일명 불신), 인코딩 자동판별, 누락 마스크 3구간 제외(계약 §1의 정밀 시각 구간), **'타슈관제센터' 대여·반납 행 모두 제외**(ST1220에서 월 1.2만 건 재배치 '대여' 유출 실측 — 2026-09-14 개정), 완전 행 5키 dedupe(계약 §7), 모든 시각 Asia/Seoul.

## 2. 모델 구조 — 3층

```
[1층: 수요 학습]  LightGBM 회귀 ×2 (objective=poisson)
   입력: 피처 벡터(아래 표)  →  출력: 15분당 대여율 λ̂, 반납률 μ̂
[2층: 확률화]  포아송/음이항 분포
   λ̂, μ̂, 현재 잔여 s  →  예상 잔여 = s + μ̂·h − λ̂·h (h=지평/15분)
                       →  고갈 확률 = P(유출−유입 ≥ s)  (Skellam, 근사식 가능)
[3층: 서빙]  매분 전체 대여소 × 지평(5/10/15분) 배치 계산 → 캐시(DB/Redis)
   여정 API·화면은 캐시 조회만 (요청별 추론 금지)
```

후반 확장(스냅샷 3주 확보 시): **모델 2 — 분류기**(입력 동일 + 현재 잔여·최근 추이, 라벨 = "15분 뒤 잔여 0") → predict_proba로 학습된 확률. 2층의 분포 확률과 캘리브레이션 비교(어블레이션 슬라이드).

## 3. 피처 명세 (우선순위 실측 근거 순)

| 피처 | 근거 (실측) |
|---|---|
| 시간당 강수 (실황+예보) | 1mm+ 시 수요 7%로 급감, 강한비 4% |
| 요일 × 시간대(15분 버킷) | 주차 간 반복성 0.983 |
| 공휴일 유형 (명절/일반/대체/근로자의날) | 설 33% / 어린이날 60% / 대체 75% |
| 기온 (+계절·시간대 상호작용) | 겨울 상관 +0.71(총량), 폭염은 시간 재배치(한낮 −34%) |
| 마지막 강수 후 경과시간 | 그침 직후 67% → 2시간째 119% (지연 반등) |
| 대여소 평소 수요 프로파일 (요일·시간별 평균) | 대여소 정체성 인코딩 |
| 직전 30~60분 실측 대여·반납 (실시간 전용) | 단기 모멘텀 — 서빙 시 스냅샷 DB에서 |
| (확장) 지하철 인접 × 시간대 | 역별 승하차 공간 조인 |

**누출 금지**: 예측 시점 t 이후의 어떤 값도 피처에 넣지 않는다. 예보는 t 시점에 발표된 예보만.

## 4. 확률화 층의 분포 선택 (실측 완료)

과산포 검증 결과(같은 계절·비<1mm 평일·15분 버킷): 분산/평균 중앙값 **1.14**, 고수요(2건+/15분) 셀 **1.33**. 포아송 근사 정확도: 저·중수요 분포 일치 95~97%, 고수요 92%, 꼬리(고갈 방향) 확률은 실측이 예측의 1.03~1.28배(낙관 편향).

→ **결정**: 포아송으로 시작, 고수요 대여소는 꼬리에 보정 계수(1.1~1.3) 또는 음이항 교체. 최종 판정은 스냅샷 캘리브레이션 → **확정(2026-09-17)**: 9/9~9/16 홀드아웃 결정 구간(s≥1)에서 실측/예측 1.12~1.34배, Brier 최소 계수 5/10/15분 = 1.35/1.25/1.20 → 단일값 **1.25** 서빙 적용(`config.TAIL_CORRECTION`). 음이항 교체는 불필요. ⚠ 과산포 검증은 반드시 날씨·계절 통제 후 수행(혼합 시 1.34~2.2로 부풀어 보임 — 직접 확인한 함정).

## 5. 학습·평가 프로토콜

- **분할 (확정)**: `bucket_start < 2026-01-01 00:00 KST` 학습 / `≥ 2026-01-01` 검증(3개월). 랜덤 분할 금지. 사용 월은 실제 대여일시 기준 월별 히스토그램으로 확정(파일명 불신). 신규 대여소(학습 구간에 없음)는 profile NaN 유지·분리 평가.
- **피처 상세·전처리 규칙의 원본은 `피처_스키마_계약.md`** — 스키마, delta 정의, 버킷 경계, 0-fill 순서, 날씨 발표지연 정렬, 서빙 계산 규칙 전부 그 문서가 기준.
- **회귀(λ, μ) 지표**: Poisson deviance, MAE. 비교 베이스라인 = ①과거 평균(요일·시간별) ②모양×크기 분해 모델(시간별 R² 0.83 실측 — 이겨야 할 선).
- **확률 지표**: Brier score, PR-AUC(고갈은 희귀 이벤트 — accuracy 금지), 캘리브레이션 곡선(3주 스냅샷).
- **censored demand 주의**: 이력 대여 수는 충족된 수요 — 고갈 상태 시간대는 수요 과소 기록. 대응: (추정) 잔여 0 근접 구간 학습 제외 또는 한계로 명시(오차 방향이 보수적임).

## 6. 검증 계획 (이중 베이스라인 + 3종 검증)

1. **분포 검증** (완료): 분산/평균 검사 + 히스토그램 대조 — §4 수치
2. **캘리브레이션** (스냅샷): "확률 70~80%라고 한 순간들의 실제 고갈율이 그 구간인가" — 구간별 곡선, 낙관 편향 시 보정 계수 적용
3. **백테스트** (스냅샷 리플레이): 추천 여정 vs "현재 잔여 기준 최단 여정" — 헛걸음 감소율 N%, 평균 이동시간 차이 산출 (발표 핵심 수치)

## 7. 일정 (남은 기간 기준)

| 주차 | AI 파트 작업 |
|---|---|
| 1주차 | 수집기 가동(최우선·소급 불가), 대여이력 전처리 파이프라인, 15분 버킷 집계 테이블 생성 |
| 2주차 | 피처 조인(날씨·공휴일), λ/μ 회귀 학습 + 베이스라인 2종 비교, 과산포 보정 계수 산출 |
| 3주차 | 확률화 층 + 서빙(매분 배치→캐시) 연결, 여정 API에 확률 공급 시작 |
| 4주차 | 스냅샷 1~2주치로 1차 캘리브레이션 → 보정/음이항 판단. (선택) 분류기 학습 시작 |
| 5주차~ | 백테스트 시뮬레이터용 로그 검증, 최종 캘리브레이션, 어블레이션 비교, 발표 수치 확정 |

## 8. 기술 스택 요약

Python + pandas/Spark(전처리, 44개월 배치) · LightGBM(회귀 poisson, 후반 분류기) · scipy(포아송/Skellam/음이항) · sklearn(캘리브레이션 isotonic, 지표) · FastAPI(서빙) · Redis/PostgreSQL(예측 캐시) · joblib(모델 저장). GPU 불필요, LLM 불필요(예측의 심장은 GBM — LLM은 추천 사유 문구 생성 등 장식 옵션).

## 9. 자주 밟는 함정 (팀 공유)

미래 정보 누출 / 랜덤 분할 / naive datetime(UTC 어긋남 9시간) / 0건 버킷 누락(집계 시 0을 채워야 분포·분산이 맞음 — 대수적 처리 가능) / accuracy로 평가 / 계절 혼합 상태로 분산 검증 / "예상 N대"를 점 추정으로 표시(구간 표기+위험 배지 병기가 결정 사항)
