## 4. 이미 만들어진 공통 컴포넌트

전부 `@/features/admin/ui/`에 있다. **새로 만들기 전에 여기부터 볼 것.**

### AdminButton

```tsx
<AdminButton>내보내기</AdminButton>
<AdminButton variant="secondary">취소</AdminButton>
<AdminButton variant="danger">삭제</AdminButton>
<AdminButton variant="ghost">닫기</AdminButton>
<AdminButton size="sm">처리</AdminButton>
<AdminButton size="lg" full>로그인</AdminButton>
```

변형 4종은 Figma `Admin/Button`과 1:1. 크기는 `sm` 32px(표 안) / `md` 38px(기본) / `lg` 44px(로그인).

### AdminBadge

```tsx
<AdminBadge state="미해결" />
```

`미해결` `처리중` `해결됨` `정상` `정지` 5종. 라벨이 곧 상태값이라 따로 안 받는다. 서버 enum(`OPEN` 등)을 한글로 바꾸는 건 **각 화면에서** 한다.

### AdminTable + AdminPagination

컬럼을 props로 받는 범용 표가 **아니다.** 여백·구분선·헤더 색만 주는 껍데기다.

```tsx
<AdminTable clickableRows>
  <thead>
    <tr>
      <th className="w-24">제보 ID</th>
      <th>제보 내용</th>
      <th className="w-16 text-right">신고</th>
    </tr>
  </thead>
  <tbody>
    {rows.map((row) => (
      <tr key={row.id}>
        <td>{row.id}</td>
        <td className="truncate">{row.body}</td>
        <td className="text-right tabular-nums">{row.reportCnt}</td>
      </tr>
    ))}
  </tbody>
</AdminTable>
<AdminPagination page={page} pageSize={12} totalCount={366} onChange={setPage} />
```

- `table-fixed`다. 폭은 `<th className="w-28">`로 준다. 안 준 칸끼리 남은 자리를 나눠 갖는다
- 셀 안 줄바꿈은 막혀 있다. 안 막으면 `TS-04821`이나 날짜가 두 줄로 쪼개져 표를 훑기 어렵다. 긴 글 칸에는 `truncate`를 붙여 말줄임
- 페이지 번호 계산은 `@/shared/lib/pagination`의 `getPageItems` (테스트 있음)

### AdminFilters

```tsx
<AdminFilterBar>
  <AdminSearchInput placeholder="자전거 ID 검색" className="w-80" />
  <AdminDateRange from={from} to={to} onFromChange={setFrom} onToChange={setTo} />
  <AdminSelect defaultValue="newest">
    <option value="newest">최신순</option>
  </AdminSelect>
</AdminFilterBar>
```

### AdminModal

네이티브 `<dialog>`를 쓴다. ESC·포커스 가두기·바깥 클릭 닫기는 브라우저가 해 준다.

```tsx
<AdminModal
  open={open}
  onClose={close}
  title="공지사항을 삭제할까요?"
  size="sm"
  footer={
    <>
      <AdminButton variant="secondary" onClick={close}>취소</AdminButton>
      <AdminButton variant="danger" onClick={remove}>삭제</AdminButton>
    </>
  }
>
  <p className="text-sm text-admin-muted">삭제한 공지는 되돌릴 수 없습니다.</p>
</AdminModal>
```

크기는 `sm` 400 / `md` 520 / `lg` 720.

### AdminToast

```tsx
const { message, showToast } = useToast(); // @/shared/lib/useToast
showToast('제보 상태가 변경되었습니다');
{message && <AdminToast message={message} />}
```

## 5. 지켜야 할 규칙

뒤집기 전에 먼저 이야기할 것. 이유가 있다.

**색은 토큰만 쓴다.** 하드코딩 hex 금지. 관리자 색은 `src/app/index.css`의 `@theme`에 `--color-admin-*`으로 모여 있다. 색을 바꿔야 하면 사용처가 아니라 토큰 값을 고친다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `admin-sidebar` / `admin-sidebar-active` | `#1c1c1e` / `#2c2c2e` | 사이드바 |
| `admin-indicator` | `#7cb342` | 활성 메뉴 왼쪽 막대, 포커스 링 |
| `admin-bg` / `admin-panel` / `admin-line` | `#ffffff` / `#f4f4f5` / `#e4e4e7` | 본문·카드·구분선 |
| `admin-text` / `admin-muted` | `#18181b` / `#71717a` | 글자 |
| `admin-danger-*` / `admin-warn-*` / `admin-ok-*` | | 배지 3역할 |

**Figma는 전체 다크지만 우리는 안 따른다.** 차콜 사이드바 + 화이트 본문으로 간다. 표가 빽빽하고 오래 보는 화면이라 본문 다크는 가독성이 떨어지고, 브랜드 그린을 아껴 쓰니 상태 배지가 먼저 눈에 들어온다.

**다크 모드·반응형은 안 만든다.** 데스크톱 1440 고정.

**모바일 `shared/ui/`는 재사용하지 않는다.** `Button`은 48px 터치 타깃에 변형도 다르다. 합치면 양쪽에 `size`·`platform` 분기가 생겨 둘 다 읽기 나빠진다. Figma도 `Admin/Button`을 별도 컴포넌트로 둔다.

**단, 순수 로직은 `shared/lib/`으로 올려 같이 쓴다.** 지금까지 `pagination.ts`(페이지 번호 계산), `useToast.ts`(토스트 타이밍). 모바일 쪽 import가 바뀌니 MR에 반드시 적을 것.

**차트는 라이브러리 없이 SVG로 직접 그린다.** 관리자 전체에서 차트는 이슈 4의 7일 막대그래프 **하나뿐이다**(히트맵은 지도 오버레이, 통계 카드는 그냥 숫자). 하나 때문에 50~150KB 의존성을 넣지 않는다. `<rect>` 높이 = 값 × 배율이 전부다.

**지도는 `map/lib/naverMaps.ts`의 `loadNaverMaps()`만 공유한다.** `MapView.tsx`는 재사용하지 않는다 — props가 전부 모바일 길안내 전용(`destination`, `routes`, `followLocation`)이라 경로선·바텀시트 컴포넌트까지 관리자 청크로 딸려 온다.

**제보 = `claim`, 신고 = `report`.** 화면에 보이는 이름은 "제보 관리"지만 경로·파일·타입은 API 용어를 따른다(`/admin/claims`). `report`는 허위 제보를 신고하는 별개 기능이다.

**관리자 화면은 라우터 lazy 청크를 유지한다.** 모바일 사용자가 관리자 코드를 내려받지 않게.

**세션 확인·로그인 요청에는 `skipAuthRedirect`를 붙인다.** `client.ts`에 "401이면 로그인 화면으로 보낸다"는 전역 규칙이 있는데 `window.location.assign`이라 **페이지를 통째로 다시 받는다.** 401이 정상인 요청(로그인 시도, 세션 확인)에까지 걸리면 가드의 `<Navigate>`(React가 화면만 교체) 대신 전체 새로고침이 일어나 느리고 상태가 날아간다.

## 6. 남은 이슈별 메모

경로는 전부 `/api` 뒤에 붙는다. "구현"은 API 명세의 구현 여부 열 기준이라 실제로 도는지는 붙여 봐야 안다.

### 이슈 3 — 히트맵 홈 (Figma 01)

`GET /admin/heatmap?date=` → `{time, stationId, xPos, yPos, rentCnt, returnCnt}[]` — **구현 O**

날짜 선택, 대여/반납 세그먼트 토글, 0~23시 시간대 슬라이더, 이전/재생/다음, 지도 위 히트맵 레이어. 마커 클릭 시 대여소 상세로.

- 응답이 `time` 단위로 오니 **하루치를 한 번 받아 프론트에서 필터링**할 것. 슬라이더를 움직일 때마다 요청하면 재생 버튼이 끊긴다
- 지도는 `loadNaverMaps()`로 SDK만 띄우고 관리자용 컴포넌트를 새로 만든다
- 현재 `AdminHeatmapPage.tsx`는 제목만 있다

### 이슈 4 — 대여소 상세 (Figma 02)

- `GET /admin/station/{stationId}` — **구현 O**
- `GET /admin/station/trend?term=` → `{date, rentalCnt, returnCnt}[]` — **구현 O**

통계 4카드(어제 대비 증감 포함), 7일 대여/반납 막대그래프, 배치 자전거 목록. 페이지 파일을 새로 만들고 라우트를 추가해야 한다.

### 이슈 5 — 사용자 관리 (Figma 04·09·09-b·09-c·09-d)

- `GET /admin/user/list?statement=&order=` — 구현 O
- `GET /admin/user/{userId}` — **구현 X**
- `POST /admin/user/{userId}/ban`, `/un-ban` — 구현 O

가장 크다. 목록과 상세를 나눠 커밋할 것. 상세는 "이용 기록" / "밴 이력" 두 탭.

**밴 기능의 우선순위가 문서마다 다르다.** 요구사항 명세 "차후 구현" / Figma "차후 구현" 배지 / API 명세 구현 여부 O(백엔드 코드도 있음). **착수 전 정리 필요.**

### 이슈 6 — 자전거 관리 (Figma 05·07·07-b)

- `GET /admin/cycle/list?cycle=&stationName=&statement=&hasClaim=` — 구현 O
- `GET /admin/cycle/{cycleId}` (이용 이력) — 구현 O
- `GET /admin/cycle/statics`, `GET /admin/cycle/{cycleId}/statics` — 구현 O
- `GET /admin/cycle/{cycleId}/claim` — **구현 X**

상세는 "이용 이력" / "제보" 두 탭. 제보 카드 UI가 이슈 7과 겹치니 먼저 끝나는 쪽이 공통으로 빼고 다른 쪽이 재사용한다.

### 이슈 7 — 제보 관리 (Figma 03·03-a·03-b)

- `GET /admin/cycle/claim?nickname=&cycleId=&order=&status=` — **구현 X**
- `GET /admin/cycle/claim/{claimId}` — **구현 X**
- `PATCH /admin/cycle/claim/{claimId}` `{statement, content}` — **구현 X**

API가 전부 미구현이라 MSW 목업 기준으로 진행. 상태 통계 3카드 + 필터 + 상세 모달에서 상태 변경 → 토스트.

### 이슈 8 — 공지사항 (Figma 06·06-a·08·08-a)

- `GET /notice/list`, `GET /notice/{noticeId}` — 구현 O
- `POST /admin/notice` `{title, content}` — **구현 X**
- `DELETE /admin/notice/{noticeId}` — **구현 X**

제목 0/60, 내용 0/2000 글자 수 카운터. **이미지 첨부 없음**(Figma에 "사진은 첨부할 수 없습니다" 명시).

## 7. 백엔드 답 기다리는 것

**관리자 로그인 API가 API 명세에 없다.** 요구사항 명세엔 "관리자 계정으로 관리자 페이지에 로그인한다(반필수)"가 있고 백엔드에 `AdminEntity`(id·password)와 `@currentAdminId`도 있는데 엔드포인트만 없다. 아래를 가정하고 목업으로 만들어 뒀다.

```
POST /admin/auth/login    {id, password} → httpOnly 쿠키
GET  /admin/auth/me       → {adminId, id, name, email}, 미로그인 401
POST /admin/auth/logout
```

확정되면 `src/mocks/handlers.ts`의 관리자 블록(가짜 세션 + 핸들러 3개)만 지우면 되고 화면 코드는 안 바뀐다. 지울 위치에 주석을 달아 뒀다.

`AdminEntity`에 `name`·`email` 컬럼이 없다. 사이드바 하단 프로필에 필요하니 컬럼 추가가 가능한지도 물어봐야 한다.

## 8. Figma에서 확인 못 한 값

팀 Figma가 Starter 요금제라 MCP 호출 한도에 걸려 컴포넌트 **내부**를 못 봤다. 아래는 추정값이니 실제 디자인과 대조 후 고칠 것. 전부 한 파일에서 클래스만 바꾸면 된다.

- 버튼 모서리 `rounded-md`(6px), 배지 `rounded-full`, 모달 `rounded-xl`(12px)
- 표 행 높이 57px(배지·버튼 있는 행) / 44px(글자만)
- 비밀번호 칸 오른쪽의 14px 원형 요소 — 표시/숨김 토글인지 확인 필요. 지금은 안 넣었다

확인된 것: 사이드바에 **아이콘 없음**, 하단에 프로필(이름·이메일) + 로그아웃 있음.

## 9. 작업 방식

- 이슈는 GitLab에 직접 등록하고 `feat/#{번호}-{기능명}` 브랜치를 `develop`에서 딴다
- 커밋 전 `npm run lint && npm test && npm run build`를 통과시킨다
- 공용 파일(`src/shared/`, `src/app/`)을 고쳤으면 MR에 반드시 적는다. 모바일 화면에 영향이 간다
